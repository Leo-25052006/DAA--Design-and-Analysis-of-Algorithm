The Greedy Method

Always grab the best thing right now. Build a spanning tree edge by edge and see exactly when greedy works.

Analogy: at a buffet with one small plate, you grab the tastiest thing in front of you, then the next, and never put anything back. That is a greedy algorithm.

⚠ Greedy can fail. With coins {1, 3, 4} and target 6, greedy picks 4+1+1 (three coins) but 3+3 (two coins) is better. Greedy needs a proof, not a hunch.

Prim's algorithm reaches the same answer differently: it grows one tree from a start vertex, always adding the cheapest edge to a new vertex (from vertex 1: 10, 25, 22, 12, 16, 14). Both give an MST of cost 99. Prim takes O(E log V) with a binary heap; Kruskal takes O(E log E) = O(E log V), using union-find to detect cycles.

Why can't Dijkstra handle negative edges?

It finalises the nearest vertex assuming no later path can be shorter; a negative edge can break that.
