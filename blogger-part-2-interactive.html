Divide and Conquer

Don't just read about algorithms. Race them, play against them and watch them think.

1The Big Idea

Divide
Split the problem into smaller subproblems
Conquer
Solve each one, usually recursively
Combine
Stitch the answers into one
T(n) = a · T(n/b) + f(n)

a = number of subproblems, b = how much the input shrinks, f(n) = cost of dividing and combining. Pros: beats brute force, cache-friendly, parallelises well. Cons: recursion eats stack memory.

2Game: Can I Guess Your Number?

Think of any number from 1 to 100 and keep it secret. I'll guess using binary search: always the middle of what's left.

Every answer halves the possibilities, so 100 numbers need at most 7 guesses. Formally T(n) = T(n/2) + O(1), which is O(log n). A million items need about 20.

int binarysearch(data[], low, high, target) {
    if (high >= low) {
        mid = (low + high) / 2;
        if (data[mid] == target) return mid;
        if (data[mid] >  target) return binarysearch(data, low, mid-1, target);
        return binarysearch(data, mid+1, high, target);
    }
    return -1;
}

Merge sort splits in half, sorts each half, then merges like zipping two sorted decks: O(n log n) always, with O(n) extra space. Quick sort picks a pivot, puts smaller items left and larger right, then recurses.

4Min/Max and Strassen

Min/Max
Find min and max of each half recursively, then compare. T(n) = 2T(n/2) + O(1) = O(n). Try [3,5,1,8,2]: answer (1, 8).
Strassen
Naive block multiplication needs 8 sub-multiplications; Strassen needs 7. T(n) = 7T(n/2) + O(n²) = O(n2.81).
P1=(a+d)(e+h)  P2=(c+d)e  P3=a(f-h)  P4=d(g-e)  P5=(a+b)h  P6=(c-a)(e+f)  P7=(b-d)(g+h)
top-left = P1+P4-P5+P7    top-right = P3+P5
bottom-left = P2+P4       bottom-right = P1-P2+P3+P6

6Test Yourself

What is the most guesses binary search needs for 100 numbers?

7, since log₂100 is about 6.6.

Why is merge sort O(n log n) in every case?

There are log n levels of splitting, and each level does O(n) merging work, whatever the input order.

Run bubble sort and merge sort. Why is the gap so big?

Bubble sort is O(n²) and merge sort is O(n log n), and the gap widens as n grows.
